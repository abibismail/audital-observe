# Audital Observe production-readiness gates (v0.2)

v0.2 is a **runnable continuous engine, validated locally** (unit, Docker PostgreSQL RLS, opt-in live GitHub). It is **not deployed** (no AWS) and **not published** (no npm). Status per gate: ✅ done and tested in v0.2 · 🟡 partial · ⛔ HOLD.

1. **Durable tenant isolation**: 🟡. PostgreSQL migrations 001/002 with FORCE RLS (tenant + project), a non-owner `NOBYPASSRLS` app role with column-level grants, transaction-local identity, append-only evidence, and narrow `SECURITY DEFINER` paths. A physical cross-tenant read/write-denial suite passes (`npm run test:pg`). Still required: managed-PG role model (RDS has no superuser), connection-level TLS, backup/PITR, a down-migration/restore runbook, and an independent review of the definer functions.
2. **Provider credential custody**: ⛔. The `DevEnvelopeVault` (AES-256-GCM, HKDF subkeys, keyed AAD binding) seals target lookups, GitHub tokens and alert endpoints. Before production: replace it with KMS envelope encryption, per-tenant keys, audited decrypts, rotation and revocation. Fine-grained GitHub token permissions cannot be introspected; prefer a GitHub App with `issues:read` + `metadata:read`.
3. **Reconciliation workers**: 🟡. Lease-based scheduler (`FOR UPDATE SKIP LOCKED`), per-claim exponential backoff, max attempts/age, finalisation, sealed-lookup deletion, rate-limit backoff and a budget floor are done. Still required: a separate worker process and horizontal scaling, per-tenant quotas, conditional requests (ETag) to save budget, and repo-level event watermarks for ghost-write detection beyond claimed issues.
4. **OTLP compatibility**: 🟡. OTLP/JSON traces and logs with semconv `execute_tool`, plus Claude Code, LangSmith, Langfuse and OpenInference mappings, are done. Codex `codex.tool_result` attribute names are not fully published upstream, so its mapping is best effort. Still required: OTLP protobuf and gRPC, gzip, and partial-success responses.
5. **Webhook/PR distribution**: 🟡. Slack and signed webhooks, an outbox with dedupe and retry, expiring share links, Check Run and PR-comment payloads, and an example customer workflow are done. Still required: DNS-rebinding-safe egress (resolve-then-pin, a deny-list for private ranges at connect time), per-endpoint rate limits, opt-out, and a GitHub App for one-click installs.
6. **Privacy**: ⛔. HMACs are pseudonymous, **not anonymous**. Still required: a UK GDPR basis, retention and deletion (evidence is append-only, so deletion must be cryptographic erasure via per-project key destruction), export, and HMAC master rotation.
7. **Evidence integrity**: 🟡. The attestation split, pinned trust registry, deep canonical JSON (survives jsonb) and append-only storage are done. Still required: the **hosted key ceremony** (an HSM/KMS-held Ed25519 key, publishing its public key in `trust/hosted-keys.json` with validity windows), public-key discovery, a revocation list, and a transparency log.
8. **Assurance**: 🟡. Incomplete pagination, rate limits, unproven coverage and missing lookups all yield `UNOBSERVABLE`. An effect that was observed and then reverted is no longer mislabelled `PHANTOM_SUCCESS`. GitHub was tested live (anonymous, public issue); Stripe remains mocked.
9. **Operating readiness**: ⛔. Auth brute-force protection, TLS termination, quotas, abuse resistance, log redaction review, SLOs, a deployment pipeline and a penetration test.
10. **Commercial readiness**: ⛔. Onboarding, billing, metering and an API compatibility policy, plus the upgrade path to Audital Guard without conflating assurance claims.

Do not enable production, live write actions, paid billing or self-service exposure until the relevant gates independently pass. Audital Guard G01–G12 remain HOLD.
